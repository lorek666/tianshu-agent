# 天枢桌面界面（M5）

Vite + React 19 + TypeScript 的单页应用。它不是独立应用：页面由**本机 Host**
加载（Host 提供回环 HTTP 服务并注入访问令牌），界面只负责展示与下发命令。
构建产物 `ui/dist/` 已提交进仓库，运行时**不需要 Node**。

## 快速开始

### 1. 起后端（推荐）

M5 的 Host 由本仓库后端工单提供。预期启动方式是：

```bash
tianshu host
```

它会在本机回环地址上提供界面，并把访问令牌注入 `index.html` 的
`<meta name="tianshu-token" content="…">`；按它给出的地址打开即可。
如果当前分支上 `tianshu host` 还没合入，先用下面的演示模式看界面。

> 端口由 Host 随机选择，页面与 `/rpc`、`/state`、`/events` 同源。界面不接受
> 手工填写端口或地址。

### 2. 复现构建（CI / 干净机器）

```bash
pnpm --dir ui install --frozen-lockfile
pnpm --dir ui run typecheck
pnpm --dir ui run test
pnpm --dir ui run build
```

- 依赖锁：`ui/pnpm-lock.yaml`；`ui/node_modules` 不提交。
- `ui/pnpm-workspace.yaml` 只把 `esbuild` 的 postinstall 加入白名单（Vite 构建必需），
  并保留 pnpm 最小发布年龄策略对 vite 的例外记录。
- `ui/dist/` **要提交**（Host 直接加载它）。仓库根 `.gitignore` 里的 `dist/` 规则
  由 `ui/.gitignore` 的反向规则覆盖，不是漏配。
- `vite.config.ts` 使用 `base: "./"`，`ui/dist/index.html` 里的资源引用是相对路径
  （`./assets/…`），Local 文件/自托管/Host 内嵌都能加载。

### 3. 没有后端时的静态预览

演示数据完全打在产物里，**不发网络请求、不读写真实文件、不写事件日志**：

```bash
# 任选一个本地静态服务器；这里用 Python 自带的
python3 -m http.server 8000 --directory ui/dist
```

然后打开 <http://127.0.0.1:8000/?demo=1>。页面顶部会显示「演示模式」，在其中
可以点审批的允许/拒绝、开始运行、暂停/取消、撤销，事件与状态都由内存里的示例
世界模拟推送。

> 直接双击 `ui/dist/index.html`（`file://`）不行：现代浏览器会拦截 file:// 下的
> ES module。用上面的静态服务器即可，仍然不需要 Node。

## 界面结构

| 区域 | 内容 |
|---|---|
| 顶部 | 品牌、守护进程版本/启动时间、事件流连接状态、刷新 |
| 左侧 | 任务列表（人话状态、当前运行、待审批数量、更新时间）、新建任务 |
| 中间上 | 任务详情：目标（可修改）、绑定目录与只读/可写、运行历史 |
| 中间下 | 运行详情：状态机人话、效果语义（`partial`/`unknown` 醒目提示）、暂停/继续/取消、累计成本、撤销入口、事件时间线 |
| 右侧 | 待审批卡片：动作、涉及文件、原因、触发规则；允许/拒绝一次点击 |
| 底部 | 事件流状态、已同步的事件序号、数据目录、立即刷新 |

`partial` 固定显示「已停止，但部分修改已生效」；`unknown` 固定显示
「无法确认是否已生效」。机器枚举（`state` / `outcome` / `effect_state` /
`action` / `rule_id`）不会出现在主界面；原始 `type` / `rule_id` / `payload`
只在每条事件的「详情」折叠区里出现（PRD 决策 D1）。

## 连接与恢复语义

- 令牌只在页面加载时从 `<meta name="tianshu-token">` 读进内存。**不写
  localStorage / sessionStorage、不进 URL、不打日志**。读不到令牌时显示
  「无法连接守护进程」，并给出启动 Host 的提示。
- 所有请求带 `X-Tianshu-Token`：`POST /rpc`、`GET /state`、
  `GET /events?since_seq=N`。
- SSE 用 `fetch` 读取 `text/event-stream`，**不是**浏览器 `EventSource`：
  契约要求每个请求带自定义 header，而 `EventSource` 天生带不了；用 fetch
  流可以达到同样的协议与重连语义。
- 重连游标 = 已收到的最大 `seq + 1`。服务端补齐后继续推增量；如果流正常
  结束（首屏补齐模式），客户端会重新带新游标发起，并额外拉一次
  `events.run` / `/state` 兜底。
- 连续 4 次连接失败（首次连接 + 3 次重连）后**停止自动重连**，显示
  「与守护进程的连接已断开，正在重试…」并提供手动「重试」按钮；期间
  3 秒轮询仍在跑，界面不会变成死页面。
- 首屏与每 3 秒轮询都重新读 `/state`；运行详情用 `events.run` 增量 +
  SSE 追加。界面不把任何业务状态写进浏览器，重开页面只是重新从
  `/state` + 事件日志重建视图。

## M5 退出条件在 UI 侧能证明什么

- **关掉界面任务继续**：界面不驱动任务，也不持有任务状态；关闭窗口只是断开
  SSE/轮询。任务是否继续由守护进程决定。**UI 侧无法证明“关闭期间任务确实
  继续了”**，那需要后端的事件日志/进程证据。
- **重开后从事件恢复**：可以证明。重新打开界面 → 读 `/state` 快照 → 用
  `events.run` 从事件日志补齐时间线/成本/效果结论；界面不做任何本地持久化。
  底部的事件序号就是这次重建的水位。
- 审批/控制命令存在并发：审批决定成功后界面**不做乐观更新**，等下一帧
  `/state` 或服务端事件确认——你点「允许」时另一个窗口可能已经拒绝，乐观
  更新会骗人。

## 演示模式的边界

`?demo=1` 是给评审用的**内置虚构数据**（`src/demo/`），不是产品功能：
它实现了同样的 RPC 方法签名，动作后用定时器推送模拟事件；它不知道真实
工作区，也不会调用模型。真实 Host 加载页面时不带这个参数。

## 已知限制（不吹牛）

- 界面没有自己的业务状态存储；Host 掉线时展示的是最后一次成功拉到的快照，
  并明确标注连接中断。
- 成本按契约支持两种形状：`payload.cost` 裸数字按美元、F13 的
  `{cost: <微美元整数>, currency}` 按微美元；主显示固定两位小数，不足一美分
  时会额外说明（不会把“花了钱”显示成“没花钱”）。未知成本单独计数，不混成 0。
- 只做了浅色主题；没做深色模式、无障碍专项审计、移动端深度适配（窄窗口会
  退化为上下堆叠）。
- 事件时间线最多保留最近 2000 条（界面内存上限），更早的会明确提示未加载。
- 演示模式下的“允许/拒绝/撤销”只改内存数据；真实撤销的最终结果以
  `undo.apply` 返回与后续事件为准。

```
ui/
├─ index.html             Host 注入 token 的入口（meta）
├─ vite.config.ts         base "./"、dist 输出
├─ src/
│  ├─ App.tsx             首屏编排、轮询/SSE、选择与命令
│  ├─ api/                契约类型、真实 Host 客户端、SSE 解析与重连、归一化
│  ├─ components/         任务/运行/审批/时间线/弹窗/连接页
│  ├─ lib/humanize.ts     枚举→中文、事件→一句人话（单测覆盖）
│  ├─ lib/timeline.ts     事件合并/去重、成本累计
│  ├─ lib/format.ts       金额、时间、路径展示
│  └─ demo/               静态预览用的内存示例世界
└─ dist/                  构建产物（提交；Host 直接加载）
```
