# 摘要缓存遥测与真实实验边界

## 目标

补齐语义摘要辅助模型调用的持久化缓存遥测，使缓存报告能同时显示主调用和
辅助调用的覆盖、未知及开销。真实端点实验尚未执行，不宣称命中率、费用或质量改善。

## 设计

沿用摘要存储的独立审计路径，在同一个 SQLite 数据库增加两张可选的追加式表：
`summary_model_calls` 保存发送前的调用身份，`summary_model_usage` 保存返回后的
最终 usage 与既有成本记录。每张表以 `summary_id` 唯一绑定；不允许 UPDATE/DELETE。
它们是内部摘要存储，不新增或改变 C1–C5 消息、事件、封闭枚举或预算语义。

调用记录包含精确版本、摘要/材料/Run/attempt 身份、provider/adapter/model、
中立请求的消息哈希及调用方缓存策略。只存摘要，不存 prompt、正文、密钥或端点。
结果引用调用记录哈希，保存 C1 最终 usage 原值；未知/缺失不转成零。
结果只记录一次，不触发重试，不另行计费。

发送前必须提交调用身份。调用抛错或进程在返回结果持久化前中断，只留下调用记录，
读取时用未知 usage 表达；不得据此重发。结果持久化后即使摘要正文不合格，
仍保留其 usage。摘要正文生成、共享账本结算、历史回放的现有职责保持不变。

评测器在关库前收集根、子、followup Run 的摘要记录，报告按真实摘要身份去重。
`usage` 与 `requests` 继续表示主调用；新增 `auxiliary_requests`、`auxiliary_usage`
和 `all_usage`，避免悄悄改变既有分母。已记录但未返回的辅助调用进入未知分母，
旧数据无遥测则继续显式显示缺口。报告不能把新增记录与主调用重复相加。
保留真实 provider 的分母规则，缓存倍率未知时费用仍未知。

评测装配必须传入产品共享预算。为让离线脚本在真实预算链下提供可结算的测试回执，
`RU-D1` 子脚本显式声明固定 usage 并升级至 `1.0.1`；局部限额及判据不变。
夹具数字不代表真实模型用量，旧任务版本分母不可直接比较。

旧库只读不加表；首次产品写入时建立新表。备份的 SQLite 一致副本与全表摘要保留
两表；GC 不删除 `summary_*`。损坏、孤立、版本不支持或身份不一致的遥测不得静默
洗成有效样本。不得把遥测作为授权、重试或预算结算依据。

## 验收

- 真实 AgentLoop 的摘要返回缓存 usage，关库重开后读数与身份仍可核验。
- 摘要空白/超长、模型异常及发送后硬退出分别覆盖；未知不填零、不额外发请求。
- 删除/覆盖、重复结果、串摘要身份、损坏 JSON/版本/哈希被拒绝。
- 主消息数与回放哈希不变，预算/总用量不重复累计。
- 辅助统计包含根、子、followup，C5 安全失败与质量判据保持原义。
- 旧库、完整备份往返与 GC 保留可验证；所有本地门禁后统一候选 CI。

## 付费 A/B 前置条件

当前没有本任务明确指定的可用端点、模型、凭据及最高花费，不挪用宿主其他服务凭据。
真实实验必须固定这些输入及任务、工具、判据，每条件至少三次，保存实际调用顺序、
间隔、策略与上下文变换证据，并把摘要/compact 自身调用纳入开销。
`off` 不保证关闭服务端隐式缓存，未驱逐时不能称为冷缓存。
当前 `evaluate` 的条件标签仍是观察事实，不是随机化四条件 A/B；需要单独受控
实验才能做因果与质量收益结论。本轮补遥测不冒充该实验已经完成。
