# Seatbelt 单进程执行设计

状态：#224 的受限增量，按已授权的主循环规格 §10/§13 施工；不表示 P0-E 整体交付。

## 目标与范围

让 macOS 上不需要派生进程的命令和本地 stdio MCP，能够通过四边界的实际 subject 准入。
现有 Seatbelt 允许后代 `setsid()` 脱组，进程组清理无法证明整树退出；这条拒绝路径必须保留。

新增显式选择的 `seatbelt_leaf` 后端，继承现有文件、网络、凭据策略，
在内核 SBPL 中禁止 `process-fork`。进程可运行线程及原地 `exec`，不得创建后代。
需要 `fork`、`posix_spawn`、`subprocess` 的正常程序也会失败；
不通过临时放行、重试或回落到其他后端维持兼容。

## 方案比较与决定

- 继续只按进程组清理：不能约束脱组后代，不能开放自动四边界准入。
- 新增通用后代追踪器：必须另证追踪启动窗口、PID 复用、监护者崩溃和内核事件丢失，
  不在已有证据不足时先扩大能力。
- 单进程沙箱：牺牲派生进程能力，获得更小、可原生验证的执行范围。本批选择此方案。

默认 `local`、既有 `seatbelt`、`auto` 的选择保持不变。
用户显式配置 `TIANSHU_EXEC_BACKEND=seatbelt_leaf`；探针仍是执行前的硬门。

## 实现与证据

- 同一 SBPL 生成器接受内部 `allow_fork` 选项，旧调用默认允许，新后端固定禁止。
- 注册表只在真实 Darwin Seatbelt 可用时注册新后端；其他平台在启动前拒绝。
- 普通探针接受两条互斥证明：已创建后代并确认超时清理，或内核明确拒绝创建后代、
  且仍存活的根进程确实经过超时终止。缺失输出、启动错误、非超时或未知清理不能通过。
  改变探针语义时提升 `PROBE_VERSION`，不复用旧缓存。
- `PreparedExecution` 为新后端生成相同禁止 fork 的 profile，并将其绑定进 subject 摘要。
  独立 detached 探针仍执行；旧 Seatbelt 的脱组反例继续拒绝。
- 内部 Python 根探针和探针后代使用 `-I -S`，不从被测工作区、`PYTHONPATH`
  或 site 启动钩子导入代码；业务 argv 和工作区模块导入语义保持不变。
- 根已经被受管 `wait` 回收时，不再向可被复用的 PID/PGID 发清理信号；
  仍存活时只终止未回收的受管根，无法确认时保持未知。此结论仅适用于禁止派生的路径。
- 命令与 MCP 分别跑真实四边界准入和业务操作。覆盖 fork/posix_spawn/普通及脱组
  subprocess、超时、显式停止、宿主硬退恢复、参数或 profile 变化。
- 不修改授权来源、事件 schema、工具身份、默认审批方式或未知效果重放规则。

## 退出条件和边界

定向红绿及移除内核禁止规则的负控、受影响回归、冻结后本机全量、
lock/Ruff、独立第二读者原生探针及新的完整 required CI 均须通过。
CI 与本机环境分别记录；未测 OS/架构和用户设备不扩张声明。

本批不实现 Windows AppContainer/Job Object、不允许任意进程树、
不实现远程 MCP 沙箱。Windows 仍需独立原生机制 ADR 及原生验收；
#224 在这些条件补齐前保持未完成。
