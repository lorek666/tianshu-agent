# Windows CI：两个 runner 内的隔离 worker 对

状态：PR #228 的开发期执行设计；不改变产品契约或平台支持声明。
实现方式由本会话选择，沿用用户已授权的继续开发和既有 PR 路径。

## 原因与约束

完整 run `45142192772` 的两个 Windows 分片均在25分钟取消，未形成完整
报告；required 汇总正确失败。旧权重回放接近平衡，也不能覆盖这次绝对
工作量超时。原始日志和失败不得重跑洗绿。

仍使用两个独立 Windows runner，每个 job 保留25分钟、完整 collection、
锁文件/lint、原生 fatal handler、60秒线程栈及严格 required 汇总。
不删测试、不放宽断言、不新增依赖、不改产品源码、默认后端或授权。

## 取舍

- 再调权重：不能解决本轮两片同时超时的绝对成本，保留现有估计。
- 共享/伪造测试材料：不能替代真实执行，禁止。
- 增加 runner 或延长时限：不采用。
- 每个既有 runner 内并行两个独立 pytest worker：采用；需明确证明进程、
  临时根、退出码和报告独立，并以新原生 CI 验证真实墙钟。

目录编号扫描的候选优化已被真实探针否定：锁定 pytest 的实际分配路径
使用计数器。未修改夹具，也不把这个假设记成性能修复。

## 执行与证据

Windows pytest step 唯一直接命令仍为 `pytest_with_stacks.py`。仅显式的
worker 对参数启用开发期 supervisor；默认单 pytest 的原路径不变。
runner 0 先启动索引0/1，runner 1 先启动索引2/3，再等待各自两个 worker；
不是先等第一个结束才启动第二个。每个 worker 调用原包装器，显式传入
真实 plugin、count4、独立绝对报告路径、basetemp 和 cache_dir。
缓存与运行目录在报告上传树之外；同 checkout 不能共享 `.pytest_cache`。

stdout/stderr 直接继承，避免新增日志线程吞掉诊断。原始 job 日志可能
交错，机器验收只使用各 worker 的原始结构化报告；不重建或合并报告。
任何启动失败、worker 非零或 supervisor 中断均不得返回成功；正常测试
失败仍等待另一 worker，保留其证据。异常时终止并等待仍受管的 worker 根。
每根清理独立尝试，单根系统错误不得跳过其余根；保留首个错误并非零退出。
等待均有界，必要时强制终止后再次有界等待；已回收根不再发信号，无法确认
回收须明确报告，不能将清理尝试记成已回收。
此处不宣称 supervisor 提供 Windows 产品沙箱或任意后代监管，硬终止时
仍由 GitHub runner 的 job 取消和孤儿清理机制负责。

开发期 plugin/核验器支持封闭集 count2/count4，旧证据仍可核验，未知值
拒绝。CI 使用四个索引；两个 runner 各上传所属两份原始报告，分别下载至
`0/`、`1/`；前者只含索引0/1，后者只含索引2/3，先合并解包会抹掉
归属，因此禁止。汇总要求两个原生 job 均成功，并严格核对四报告的同一
run/attempt/checkout、完整有序 collection、确定性分区、互斥全集、
全部相位与 finish；缺失、额外文件、错 runner 归属、重复、失败或取消均拒绝。

## 验收

- 默认包装器原有诊断、fatal、负控及退出码契约继续通过。
- 真实 worker 对完成四索引互斥完整覆盖；两对父进程与四个 worker 通过
  TCP 屏障证明同时存活，不能用同进程连接或 sleep 冒充并发。
- 每 worker 的临时目录、锁根和注册根独立；使用临时数据、动态端口和
  既有隔离凭据规则，不触碰宿主生产数据。
- 真 worker 非零、启动第二个失败、中断及伪绿报告均使父调用失败，
  已启动 worker 必须被受管等待回收；完整报告仍不能覆盖失败 job。
- 完整原生 Windows CI 单独判定吞吐和本机未覆盖的 OS 行为。
