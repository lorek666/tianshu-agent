# Goal 模式实施计划

> **For agentic workers:** 使用 `superpowers:executing-plans` 按顺序实施；
> 首版 G1 由当前会话开发，冻结后由独立第二读者复审。

**Goal:** 交付可持久化、可逐轮推进、可人工验收的 Goal 首版。

**Architecture:** 新增 Goal 事件派生视图和控制面。推进复用 TaskStore/JobStore，
条件及上一轮正文保存进本轮输入快照，桌面独立面板展示与操作。

**Tech Stack:** Python 3.12 标准库、现有 SQLite 事件库、React/TypeScript。

**Spec:** [Goal 规格](../../SPEC-GOAL-MODE-2026-11-22.md)

## Global Constraints

- Python `>=3.12,<3.13`，零新增第三方运行时依赖。
- 事件 append-only，跨存储提交用 `EventLog.transaction()`。
- 首版每轮手动继续；不交付自动循环、自动验收或累计预算。
- 执行资格固定，保留原审批、预算与恢复边界。
- 契约单独提交；本地验证不冒充远端 CI 或发行交付。

## Review Focus

- 网络重试和双客户端重复推进不得多建 Run；真子进程屏障测试覆盖。
- 前轮失败、空白输出或未知副作用不能继续或验收。
- 改目标后旧 Goal 失效，旧 Run/旧 Goal 输入不能跨修订注入。
- 首轮持久化输入、游标丢失、回放与重开库必须保持一致。
- UI 切换 Task 时迟到响应不能把旧 Goal 的条件显示到新 Task。
