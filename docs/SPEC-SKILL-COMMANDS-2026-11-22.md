# 对话界面本地 Skill 接入规格

日期：2026-11-22。状态：实施规格；实现与验证状态以知识库和变更记录为准。
用户要求：先写 spec，开始接入 `/` 调用技能。本文的实现选择由开发者提出，不代表额外的产品承诺。

## 1. 目标与范围

在新建任务和已有任务的输入框中，输入 `/` 可发现本地技能，选择技能并附带要求后，
将该技能的 `SKILL.md` 快照交给现有执行或计划工作流。用户不需要手工复制文件。

首版只接入本地文本技能：不安装插件、不下载技能、不自动执行脚本、不递归装载引用文件，
不做模型自动选择技能，不引入 Python 第三方运行时依赖。Python 保持 `>=3.12,<3.13`。

## 2. 方案与取舍

1. 只在前端替换字符串：代码少，但浏览器不能可靠读取本地目录，也无法统一校验来源。
2. **后端发现与准备，复用任务目标快照（采用）**：增加只读控制面接口，
   技能正文在任务创建或修订时沿现有事件路径持久化；不修改 C1–C5 形状、工具清单和审批。
3. 独立 Skill Engine 与新事件族：可以形成结构化技能生命周期，但本轮不需要安装、
   组合或自动路由，先不扩大事件和恢复协议。

首版任务目标会包含技能快照，已有的查看/修改目标入口可审查它。
后续若要把简短展示目标与结构化技能快照分离，须另立契约，不能偷偷改历史回放语义。

## 3. 用户交互

- `/`、`/skills`、无参数 `/skill`：展示命令与技能菜单，不创建或修订任务。
- `/skill <名称或版本标识> [要求]`：显式调用一个技能。
- `/<技能名称> [要求]`：同名技能唯一时的快捷调用；未知名称明确报错，不发送普通目标。
- `/plan [要求]`、`/compact`、`/execute` 优先按既有语义处理，不被同名技能遮蔽。
- 菜单列出名称、描述及来源路径，可按名称或描述过滤；方向键移动，Enter/Tab 选择，
  Escape 关闭；输入法组合输入期间不选择或发送，Shift+Enter 保留原有输入行为。
- 菜单选择插入 `/skill <版本标识> `，不直接发送，也不改变计划模式或执行策略。
- 新建与追问共用菜单及准备逻辑。准备失败保留草稿，不创建任务、不修改目标、不启动 Run。
- 列表为空、部分技能无效、读取失败均显示可操作说明；请求过期或卸载后的响应不得覆盖新上下文。

## 4. 目录与解析

只读取以下目录的直接子目录中的 `SKILL.md`：

- 用户目录：`~/.agents/skills/<name>/SKILL.md`。
- 当前所选各工作区：`<workspace>/.agents/skills/<name>/SKILL.md`。

不扫描其他工作区、整个项目或插件缓存。未选工作区时仍可使用用户技能。
同一路径去重；不同来源同名技能全部保留，手工按短名称调用时拒绝歧义，要求从菜单选择。
工作区根须为绝对且存在的目录，canonicalize 后再使用。工作区技能目录、子目录及文件
不得解析到对应工作区/技能根之外。越界链接、非普通文件和读期间变化均报告问题。
这是有界、协作式文件观察，不是同 uid 攻击防护或物理沙箱。

每次请求最多 16 个工作区根；每个技能根最多观察 128 个直接条目，
整个列表最多返回 128 个技能；超过边界明确拒绝，不静默截断。
单文件最多 64 KiB，UTF-8 严格解码，正文不能为空，描述最多 1024 个字符。

支持 `---` frontmatter 中必填 `name` 和 `description`；名称与目录名相同，
匹配小写 ASCII 字母、数字及单连字符，长度为 1–64。
描述支持单行 plain/单引号/JSON 双引号及缩进的 `|`、`>` 文本块。
其他元数据不激活任何运行行为；不是完整 YAML 解释器，不支持模板、标签或执行表达式。

## 5. 只读 RPC V1

机器副本：`schemas/skill.json`。所有结果带 `format_version: 1`。
只允许人机控制面调用，不加入模型的 `tool_manifest()`。

`skill.list({workspace_roots?: string[]})` 返回：

```json
{
  "format_version": 1,
  "skills": [
    {
      "id": "review@0123456789ab",
      "name": "review",
      "description": "检查当前修改",
      "path": "/absolute/root/review/SKILL.md",
      "sha256": "<完整文件原始字节的 SHA-256>"
    }
  ],
  "issues": [{"path": "/absolute/path", "message": "无效技能的原因"}]
}
```

`id` 由名称及 `SHA256(规范路径 UTF-8 + NUL + 原始文件字节)` 的前 12 位构成。
内容或路径变化使选择失效；同 id 碰撞必须拒绝，不随意选中其中一个。
列表只返回元数据和摘要，不回传正文，不调用模型。

`skill.prepare({workspace_roots?: string[], skill: string, input: string})`：

- 重新执行同样的有界发现；按精确版本标识或唯一名称选择。
- `input` 最多 16384 个字符，允许为空；未知、歧义或过期标识均明确失败。
- 返回 `{format_version:1, skill:<上述描述对象>, goal:<展开后的任务目标>}`。
- `goal` 包含用户要求、V1 技能来源信息、原始 UTF-8 文件全文。
  展开不依赖模型，也不把当前时间混入快照；相同输入及文件得到相同目标。
- 列出/准备操作均不写事件、不改 Task、不创建 Run、不改变执行策略、不执行脚本。
- UI 随后沿既有 `task.create`/`task.revise`、`run.start` 提交展开目标。
  该目标被现有 `run.start.task` 固定；重放、恢复不得重新读取本地技能。

列表与准备分开是为了只把用户真正选择的一个技能送入模型上下文。
准备完成后文件再变化，不影响已经准备好的快照。任务提交失败不产生自动重试或额外模型调用。

## 6. 执行与数据边界

- 技能是用户显式选择的参考说明，不是 system 权限策略，也不是授权。
- 技能中的 `allowed-tools`、自动批准、网络要求等不能增加工具或绕过 dispatcher。
- `pure_only` 及计划模式照常拒绝写入；进入执行模式仍沿原有审批链。
- 用户技能目录不会自动成为 Task 工作区；技能引用的脚本/素材不被自动读取或运行。
- 技能快照会随任务输入发送给配置的模型；菜单明确提示这一点。
- 本轮不新增 C3 事件、C4 rule id 或持久化字段，不修改历史事件、全局锁或用户凭据。
- 演示模式返回空技能列表并解释来源，不读取真实用户目录。

## 7. 验收与发布

后端使用临时用户技能根及临时工作区覆盖：目录发现、规范路径、无效文本、
字节上限、非普通文件、同名歧义、选择失效、确定性展开及纯读取无模型/事件副作用。
真实控制面创建和驱动 Run，核对模型收到已保存全文；删除源技能后 replay 仍成功。
恶意技能要求越权时，验证计划/仅读模式不能写文件，不能靠提示文本证明权限有效。

前端覆盖两个输入框的选择、过滤、键盘/输入法、未知/过期技能、读取失败保留草稿、
失败不创建/修订任务、不改变计划模式，旧三个命令无回归；演示列表不伪造安装技能。

按 Tier 2 完成定向红绿、受影响域回归、冻结锁文件、全仓 Ruff 与前端
install/typecheck/test/build，提交对应 `ui/dist`。若实现扩大到授权、事件或恢复核心，
立即升级 Tier 1 门禁。远端 CI 与受保护 PR 合并是后续发布门禁，本地实现不代表发行交付。
