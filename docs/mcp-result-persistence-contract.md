# MCP 入站结果持久化契约

状态：契约提案。实现、迁移边界及平台验证由后续实现 PR 单独交付。

## 原方案 → 新方案

- 原方案：`tool.result.output.mcp` 和运行游标可以内嵌结果正文。Receipt 与回放依赖各自取得的副本。
- 新方案：对于新写入的 MCP 结果，先持久化一份内容寻址的 canonical JSON blob。事件、Receipt 与游标只保存自身所需的固定字段、摘要和引用。live 调用与恢复由同一份通过验证的正文重建模型消息；历史 inline 记录不改写，仍按原格式读取。
- 原因：同一次结果有多个副本时，审计查到的内容可能不是回放使用的内容。固定引用使内容、身份和实际保存的字节可独立核验，也限制事件和游标随正文膨胀。
- 影响：MCP 执行和结算、EventLog 与快照材料定位、游标与模型消息重建、Receipt/回放核对及审计 blob 保留。不改变 C3 `tool.result` 外层版本、模型可调用工具 schema 或派发授权。

## 记录与解码

- `tianshu.mcp-result.v1` 是 blob 和引用载荷的版本标记。Blob 使用严格 UTF-8、键排序、无多余空白的 JSON 编码，保留 content block 顺序、可用的结构化正文及派发元数据。拒绝重复键、非有限值、畸形编码和未知版本。单个 blob 上限为 1 MiB；读取损坏文件也有字节上限。
- 引用绑定 `content://sha256:<digest>`、`sha256`、字节数及 `after_state="mcp:<digest>"`。验证还核对 server、tool、版本、request ID、错误标记和截断、耗时元数据；一个字段不匹配就不水合。有引用标记的坏记录不能作为旧 inline 结果放行。
- 显式定位符仅允许相对 DB 父目录。配置了不同的数据根时，空的 snapshot 定位符可由可信运行配置推出固定快照 blob 目录；记录本身不能引入另一个根。拒绝绝对定位、向上逃逸及目标符号链接逃逸。该检查不提供同 UID 进程隔离。
- Blob 写入失败时不提交虚假成功或 Receipt。超过可证明的派发边界后，无法确认结果仍结算为 `unknown` 并保留人工恢复门槛。协议失败的日志只保存本地原因和可审计的分类，不把对端任意错误正文写进事件。清理其他引用时应保留仍被审计历史引用的 blob。

## 实现验收

用真正的 stdio 对端验证调用、授权内容读取、关闭重开、回放及 Receipt；覆盖保留旧 inline、合法同根与异根配置、有界读取、越界定位、符号链接、损坏内容、协议错误、提交失败及不会盲目重新派发。物理沙箱、第三方 MCP 兼容及跨机器备份恢复仍按各自门槛独立验收。
