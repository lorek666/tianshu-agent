## 1. W4 模型流式输出契约（C1 + 控制面瞬态推送）

### 原方案
- `Model.complete(messages, tools) -> ModelResponse` 仅支持整包等待返回。
- 桌面端在长文本回复或复杂工具推理期间无任何中间可见反馈，用户只能看到静态「运行中」，等待感强。

### 新方案
1. **C1 增量对象 `ModelStreamDelta`（见 [schemas/c1/model.json](../schemas/c1/model.json) `$defs.modelStreamDelta`）**：
   - `schema_version`: `"1.0"`（常量）
   - `kind`: `"text" | "tool_call_start"`（封闭二值枚举）
   - `text`: `str`（当 `kind == "text"` 时为本次新增文本片段；否则为空串 `""`）
   - `tool_name`: `str`（当 `kind == "tool_call_start"` 时为模型开始生成的工具名提示；否则为空串 `""`）
2. **适配器协议扩展（向后兼容）**：
   - `Model.complete(messages, tools)` 签名与返回值保持 100% 不变。
   - 支持流式的适配器额外实现可选方法 `stream_complete(messages, tools, on_delta: Callable[[ModelStreamDelta], None]) -> ModelResponse`：
     - `OpenAICompatibleModel`（`stream: true` SSE `data:` 行解析）与 `AnthropicMessagesModel`（`stream: true` `content_block_delta` / `message_delta` / `message_stop` SSE 解析）在收到增量块时回调 `on_delta`，并在流正常收束时返回与非流式语义完全一致的 `ModelResponse`（校验 13 值 `FINISH_REASONS`、归一化 `usage`、不替模型修复半截工具 JSON）。
     - 流中途断连、HTTP 非 2xx 或协议损坏时一律抛 `ModelError`，**绝不把半截流伪造成 `end_turn`**；已发出的瞬态增量不构成持久化结果。
     - `RecordedModel`（`replay`）与不支持流式的模型走原 `complete()`，不发射流式增量。
3. **事件日志与控制面边界（红线 1 / 红线 3 / 红线 5 守护）**：
   - **流式增量不进 SQLite `events` 表（零新增 C3 事件类型）**：逐 token 落库会导致 WAL 膨胀数十倍并污染因果序列。唯一持久化事实源依然是完整收敛后的 `model.result` 事件。
   - **派发门禁不变（PRD §5.1）**：任何工具调用绝不在流式增量阶段提前派发，必须等整轮流结束、`ModelResponse` 构造完成、参数完整通过 C2 校验且 assistant turn 持久化后才进入 `dispatcher`。
   - **控制面瞬态推送**：Daemon 订阅流新增瞬态帧 `{"kind": "model_stream", "run_id": ..., "task_id": ..., "turn_index": ..., "delta": {...}, "done": bool}`（受既有 `SEND_QUEUE_MAX` 有界队列保护；慢订阅者溢出走既有重连拉取 `state`/`events` 收敛，不阻塞主循环）；Host `/events` SSE 转发为 `event: model_stream`，React `RunTimeline` 实时展示生成中文本并在收到对应 `model.result` / `run.end` 时自动收口替换。

### 为什么这么改
- 同时满足普通用户桌面端「秒级首字反馈」与内核「append-only 事件日志精简可重放、半截流绝不误派发副作用」的双重硬约束。

### 影响哪些代码（在紧随的实现 PR 中落地）
- `src/tianshu/model.py`（`ModelStreamDelta`、`OpenAICompatibleModel.stream_complete`、`AnthropicMessagesModel.stream_complete`、`ScriptedModel.stream_complete`）
- `src/tianshu/settings_control.py`（`RuntimeModelSlot.stream_complete` 透传）
- `src/tianshu/loop.py` / `src/tianshu/worker.py` / `src/tianshu/daemon.py` / `src/tianshu/host.py`（`on_model_delta` 瞬态广播接线）
- `ui/src/api/stream.ts` / `ui/src/App.tsx` / `ui/src/components/RunTimeline.tsx`（实时流式气泡渲染与收口）

## 2. W12 C1 / C2 / C5 字段级 JSON Schema 冻结

### 原方案
- `schemas/` 下仅有 `c3/event.json`、`c4/rules.json`、`m2/*` 与 `data/restore-v1.json`；C1（Model I/O）、C2（Tool）、C5（Eval）缺少机器可校验的字段级 JSON Schema（`docs/KNOWLEDGE.md` §7「实现上的疤」）。

### 新方案
- 新增三份严格遵循 `https://json-schema.org/draft/2020-12/schema`（兼容项目纯标准库校验器 `event_schema.SUPPORTED_KEYWORDS` 子集）的机器契约：
  1. [schemas/c1/model.json](../schemas/c1/model.json)：冻结 `FINISH_REASONS`（13 值）、`ModelError.KINDS`（6 值）、`Usage`、`ToolCall`、`ModelResponse`、`ModelStreamDelta` 与规范化 `Message`。
  2. [schemas/c2/tool.json](../schemas/c2/tool.json)：冻结 `ToolSpec` 全部 10 个字段、`side_effect_level`（3 值）、`exec_model`（`E1|E3`）、`action`（7 值）以及 `tool_manifest()` 产出的函数工具 wire 清单形状。
  3. [schemas/c5/eval.json](../schemas/c5/eval.json)：冻结 `tianshu.eval.v1`（18 个顶层必填字段、`verdict` 4 值、四维评测、归因 8 层、`repeat >= 3`）与 `tianshu.eval.compare.v1` 对比报告契约。

### 为什么这么改
- 消除「手写替身掩盖契约漂移」风险，用统一纯标准库校验器把 Python 代码常量/真实运行产物与 `schemas/c1`、`schemas/c2`、`schemas/c5` 双向钉死。

### 影响哪些代码（在紧随的实现 PR 中落地）
- `tests/test_c1_c2_c5_schemas.py`：用真实 `FINISH_REASONS`、`ModelError.KINDS`、`SPECS`、`tool_manifest()`、`build_report()`、`compare_reports()` 对三份 JSON Schema 执行正负控双向校验。

## 3. C3 `run.end` 载荷升 `v2`：补齐货币成本汇总字段

### 原方案
- `run.end` v1 载荷包含 `tokens`、`tokens_unknown_calls`、`turns`、`unbilled_model_intents`、`budget_enforced`，但缺少货币成本汇总（`docs/KNOWLEDGE.md` §7 登记缺口），查看费用必须额外读取游标或账本。

### 新方案
- 参照 `run.start` 升 `v2` 的既有先例（保留 `v0` 与 `RUN_END_V1_SCHEMA` 历史读取兼容，不改写旧事件、不按新版补值），将 `run.end` 新写入升为 **`payload_version = 2`**，新增两个必填字段：
  - `cost_total_micros`: `integer | null`（`minimum: 0`；当本 Run 存在至少一次已知计价调用或零模型调用且无未知计价时为非负微美元整数；若发生过模型调用但所有调用单价均未知则为 `null`，绝不用 `0` 冒充未知价格）
  - `cost_unknown_calls`: `integer`（`minimum: 0`；单价未知的模型调用次数，源自游标 `budget_ledger.unknown_cost_calls`）

### 为什么这么改
- 履行 PRD D4 / F13「成本可见且未知不伪装成 0」承诺，使 `run.end` 自身即可完整表达一次执行的 token 与微美元结算结果，同时 100% 兼容历史 v0/v1 事件库读取与回放。

### 影响哪些代码（在紧随的实现 PR 中落地）
- `src/tianshu/event_schema.py`（保存 `RUN_END_V1_SCHEMA`、`CURRENT_SCHEMAS["run.end"]` 增两字段、`current_version("run.end") == 2`、`_RECOGNISED_VERSIONS["run.end"] = {0, 1, 2}`）
- `schemas/c3/event.json`（同步镜像 `run.end` 当前契约）
- `src/tianshu/tasks.py`（`_run_end_payload` 汇总 `cost_total_micros` 与 `cost_unknown_calls`）
- `tests/fixtures/events/minimal_v1.json`、`tests/test_event_schema.py`、`tests/test_network_fetch.py` 及新增 `run.end` v1/v2 兼容回归测试。
