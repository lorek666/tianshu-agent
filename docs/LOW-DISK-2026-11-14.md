## T3 实现范围

CLI 的 `run start` 和兼容创建入口接受
`--execution-mode {effects,pure_only}`，缺省为 `effects`。已有 Run 的
`status` / `pause` / `resume` / `cancel` 若显式携带该参数，会在打开数据库前以用法错误
返回 2；资格只能绑定新建 Run，不能原地升级。

RPC 只从 `run.start.params.execution_policy` 读取完整
`RunExecutionPolicyV1`。字段缺失时采用 effects；显式 `null`、数组、bool、浮点 `1.0`、
未来版本、未知 mode 和额外字段均返回 `bad_params`。合法策略先经过
`Dispatcher.prepare_run`，再传给同一创建层和 `TaskStore.start_run`。策略对象只限制本次
Run，不进入 `task.create`，也不改写 workspace 的 `readonly` / `writable`。

UI 的新建任务和已有任务启动两条路径都发送精确策略。新建任务启动失败后，详情重试仍保留
先前选择的 `pure_only`，不会静默退回 effects；低盘拒绝原因直接展示给用户。离线 demo
复用相同对象形状，但 demo 只证明演示接线，不替代 RPC 或后端执行证明。

原AUTH/eval/fence与硬退exit77断言未放宽。作者最终受影响联合311 passed（195.55s），
不与全量或独立用例相加。

另一层门兜住，不能声称发生写入或独立杀死该守卫；最终直接_verify断言在删该守卫时出现
两项DID NOT RAISE真红，恢复后两项通过。所有阶段见修后公开子集的author-raw，

## 本轮另发现的既有缺口

**BASE-B1（P2，未修）：CLI 引擎未装配预算账本。** 第二读者逐字节对比基线
`a0223aa269efcdf70df4c4d8c43e5629b4fa0215`、T2 与 T3，确认三者的 `cli._engine`

已经修复。其他入口的预算保留证据不能外推到 CLI；`pure_only` 仍不代表免费或零磁盘写。
精确三方源比对、离线探针、命令及输出在
[717 整分支复审 §4](evidence/low-disk-2026-11-14/integration-review-717/REPORT.md)
