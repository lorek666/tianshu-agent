# 2026-11-18 · G3-B07：W15 v2 保守离线安全 GC（`tianshu data gc`）

## 背景与契约依据

依据独立契约冻结提交 `e8d136d`（[CONTRACT-W15-RETENTION-2026-11-15.md](../CONTRACT-W15-RETENTION-2026-11-15.md) §6、[CONTRACT-PHASE2-G3-2026-11-18.md](../CONTRACT-PHASE2-G3-2026-11-18.md) §2、PRD §8.4/§8.5），在不触碰红线 1/2/5/6/11、不放宽 `summary_versions` 触发器、不引入在线 GC 的前提下，落地受管离线空间回收命令 `tianshu data gc`。

## 核心设计与安全不变量

1. **CLI 签名、退出码与 `--desktop` 桥接（`src/tianshu/data_cli.py` + `src/tianshu/cli.py`）**
   - `tianshu data gc --data-root ROOT [--older-than-days 90] [--dry-run | --approve] [--json]`（支持 `--desktop` 定向桌面端默认数据根，禁止与显式 `--data-root` 混用）。
   - **默认只读预演**（省略 `--approve` 或显式 `--dry-run`）：对静态关闭库使用 `?mode=ro&immutable=1` + `PRAGMA query_only=ON`（杜绝在已关闭 WAL 库旁创建 `-wal`/`-shm` 伴随文件），对含活跃伴随文件库使用 `?mode=ro` + `PRAGMA query_only=ON`；零文件修改、零 SQL 写语句，输出脱敏候选清单后退出 **`3`**。
   - **显式离线执行（`--approve`）**：取得 `acquire_restore_database_access(root / "events.db", exclusive=True)` 独占准入，动态查询 `restore_access._registry_factory()` 严核非恢复 `held` 隔离范围（`.restore-origin.json.tmp` / `.restore-token.json` / `.restore-token.json.tmp` 无条件拒绝；存在 `.restore-origin.json` 时必须精确匹配同批次 `OriginV1`、`SealedHoldV1`、尾阶段 `ReleasedV1`、`domain_digest("origin", origin)` 与实时 `(S, D)` 原生实体身份，严防跨批次误放行），复核 `writers_active(root) is False` 与 `check_connection` + `PRAGMA main.quick_check`，并在**独占锁内重新运行** `collect_references(root)`（根除预演至执行间的 TOCTOU 窗口）；完成后执行 `PRAGMA wal_checkpoint(TRUNCATE)` 原地截断回收 `-wal` 体积并退出 **`0`**。
   - 任何参数冲突、缺根、损坏库、未完成迁移、恢复 `held`、活跃进程持锁、未完成撤销日志（`in_progress`）或 `ReferenceUnknown`（含坏快照清单、符号链接、多硬链接、引用材料 SHA256 不符），一律 **0 文件删除、0 数据库删除**并退出 **`2`**；JSON 与文本输出对本机路径及已登记凭据全量脱敏。

2. **扩展孤儿扫描、执行流溢出证据保护与句柄级材料核验（`src/tianshu/backup.py`）**
   - `collect_references(data_root)` 与备份材料校验（`_material_references` / `verify_backup`）完整覆盖七类引用：事件外置 `payload_ref`、`run_command` 截断流溢出原文 `exec_stream_blobs`（`tool.result` / `receipt` 的 `stdout_ref` 与 `stderr_ref`，解析 `artifacts/blobs/<sha>` 与 `blobs/<sha>`）、Receipt 写前副本、快照写前副本、撤销日志引用、`content_objects` 及未擦除记忆正文；扫描 `artifacts/blobs/*` 与根 `blobs/*`（严格排除 `memory_blobs/*`），对所有受保护文件与候选孤儿执行 `_checked_file` + 原生实体句柄 `open_entity`（`link_count == 1`）+ 流式 SHA256 核验，任何缺失或篡改均记入 `unknown` 触发闭锁拒绝。

3. **绝对禁删面与四类安全清理目标（`src/tianshu/data_gc.py`）**
   - **严格 0 删除不变量**：`events`、`event_versions`、`summary_materials`/`summary_sources`/`summary_versions`、`dispatches`/`dispatch_requests`/`dispatch_meta`、`approvals`/`grants`、`runs`/`tasks`/`subtasks`、`memories`/`memory_*`、`content_objects`/`content_grants`、`budget_accounts`/`budget_limits`/`budget_counters`、非空快照清单（`changes != []`）、`artifacts/undo/*.json`、`protected_blobs`，以及任何 `state != 'settled'`、`known == 0` 或 `run_id == ''` 的 `budget_reservations` 行。
   - **仅清理四类可证安全目标**：① 未被引用的单硬链接孤儿 blob（`artifacts/blobs/*` 与 `blobs/*`）；② 超期空终态快照清单（`changes == []`、终态 Run 且 `effect_state` 非 `partial`/`unknown`、无未决 intent/活跃派发/Receipt/撤销日志/pin）；③ 超期终态且所属终态 Run 无活跃派发/子任务的 `jobs` 行；④ 超期 `settled & known=1` 且归属终态 Run 的 `budget_reservations` 行。
   - **低磁盘豁免与内核零写上限恢复路径**：不套用新副作用 Run 的 2 GiB `DiskAdmission` 下限；进入独占锁后在打开 SQLite `?mode=rw` 之前先探测有效可写余量（综合磁盘剩余空间与 POSIX `RLIMIT_FSIZE` 软上限），当余量低于 `256 KiB` 最小 WAL/SHM 安全余量（含真子进程 `RLIMIT_FSIZE=(0, 0)` 零写上限或 `0` 字节满盘）时，全程走只读连接（无旁文件时 `?mode=ro&immutable=1`，零字节分配 `-shm`/`-wal`）完成准入与二次引用核验并先行 `unlink` 孤儿文件释放空间，仅在重测余量达标后才打开写连接清理表行与截断 WAL，否则置 `db_rows_deferred_low_disk=true` 安全退 `0`。
