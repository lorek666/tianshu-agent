# 2026-11-18 · G3-B07：W15 v2 保守离线安全 GC（`tianshu data gc`）

## 背景与契约依据

依据独立契约冻结提交 `e82a3146`（[#194](https://github.com/lorek666/tianshu-agent/pull/194)）（[CONTRACT-W15-RETENTION-2026-11-15.md](../CONTRACT-W15-RETENTION-2026-11-15.md) §6、[CONTRACT-PHASE2-G3-2026-11-18.md](../CONTRACT-PHASE2-G3-2026-11-18.md) §2、PRD §8.4/§8.5），在不触碰红线 1/2/5/6/11、不放宽 `summary_versions` 触发器、不引入在线 GC 的前提下，落地受管离线空间回收命令 `tianshu data gc`。

## 核心设计与安全不变量

1. **CLI 签名、退出码与 `--desktop` 桥接（`src/tianshu/data_cli.py` + `src/tianshu/cli.py`）**
   - `tianshu data gc --data-root ROOT [--older-than-days 90] [--dry-run | --approve] [--json]`（支持 `--desktop` 定向桌面端默认数据根，禁止与显式 `--data-root` 混用）。
   - **默认只读预演**（省略 `--approve` 或显式 `--dry-run`）仅在无 `-wal`、`-shm` 和 `-journal` 时使用 `?mode=ro&immutable=1` 与 `PRAGMA query_only=ON`。读取后重核主库签名与旁文件。旁文件存在时退出 **`2`**，保留现场及未折叠提交。通过核验后输出脱敏候选清单并退出 **`3`**。
   - **显式离线执行（`--approve`）** 取得对 `root / "events.db"` 的独占组合准入。有效解除根须有与当前实体和同批次控制标记绑定的 `ReleasedV1` 证明。进程存活探针、库准入、`PRAGMA main.quick_check` 和 `collect_references(root)` 均在锁内重新核验。协作式锁约束已接线写者。正常余量的 POSIX 批次可通过真实 SQLite 读取旁文件中已提交的 WAL 引用，完成行删除、文件删除和父目录同步后执行 `PRAGMA wal_checkpoint(TRUNCATE)`。
   - 参数冲突、缺根、损坏库、未完成迁移、恢复 `held`、活跃进程持锁、未完成撤销日志（`in_progress`）或 `ReferenceUnknown`（如坏快照清单、链接、引用材料哈希不符）在预检阶段退出 **`2`**，文件与数据库行均未删除。JSON 与文本报告调用路径及凭据脱敏。

2. **扩展孤儿扫描、执行流溢出证据保护与句柄级材料核验（`src/tianshu/backup.py`）**
   - `collect_references(data_root)` 与备份材料校验（`_material_references` / `verify_backup`）完整覆盖七类引用：事件外置 `payload_ref`、`run_command` 截断流溢出原文 `exec_stream_blobs`（`tool.result` / `receipt` 的 `stdout_ref` 与 `stderr_ref`，解析 `artifacts/blobs/<sha>` 与 `blobs/<sha>`）、Receipt 写前副本、快照写前副本、撤销日志引用、`content_objects` 及未擦除记忆正文；扫描 `artifacts/blobs/*` 与根 `blobs/*`（严格排除 `memory_blobs/*`），对引用文件使用原生实体句柄（`link_count == 1`）核对身份、流式 SHA256 与登记大小，对候选核对路径和单链接文件实体。引用核验失败触发 `ReferenceUnknown`。候选必须排除受保护路径和文件身份，见 [文件身份回归](2026-11-19-w15-reference-identity.md)。

3. **绝对禁删面与四类安全清理目标（`src/tianshu/data_gc.py`）**
   - **严格 0 删除不变量**：`events`、`event_versions`、`summary_materials`/`summary_sources`/`summary_versions`、`dispatches`/`dispatch_requests`/`dispatch_meta`、`approvals`/`grants`、`runs`/`tasks`/`subtasks`、`memories`/`memory_*`、`content_objects`/`content_grants`、`budget_accounts`/`budget_limits`/`budget_counters`、非空快照清单（`changes != []`）、`artifacts/undo/*.json`、`protected_blobs`，以及任何 `state != 'settled'`、`known == 0` 或 `run_id == ''` 的 `budget_reservations` 行。
   - **仅清理四类可证安全目标**：① 未被引用的单硬链接孤儿 blob（`artifacts/blobs/*` 与 `blobs/*`）；② 超期空终态快照清单（`changes == []`、终态 Run 且 `effect_state` 非 `partial`/`unknown`、无未决 intent/活跃派发/Receipt/撤销日志/pin）；③ 超期终态且所属终态 Run 无活跃派发/子任务的 `jobs` 行；④ 超期 `settled & known=1` 且归属终态 Run 的 `budget_reservations` 行。
   - **低余量**。独占准入后测量有效余量，结合磁盘空闲空间与 POSIX `RLIMIT_FSIZE` 软上限。低于 `64 KiB` 时先在静态库上做只读预检，有 SQLite 旁文件就退出 `2` 并保留现场。POSIX 可以先删除无引用文件并同步父目录。重测达到下限后才开写连接清理表行与执行检查点。余量仍不足时退出 `0`，跳过检查点。有待删表行时报告 `db_rows_deferred_low_disk=true`。
   - **目录持久化**。POSIX 上每次 `unlink` 成功后立即计入确认效果并同步所属目录，随后才处理下一项。Windows 批准执行也先做只读预检。有文件候选时退出 `2`，整批文件、表行及检查点均保持原样。静态库的纯表行批次可以按余量执行或延期。物理掉电须单独验证。后续目录能力见 [#200](https://github.com/lorek666/tianshu-agent/issues/200)。
   - **保留期字段对账**：`jobs` 的现有表结构没有 `updated_at`。终态转换写 `ended_at`；执行以 `COALESCE(ended_at, created_at)` 严格小于截止时刻判断，旧的空结束时间回退至创建时间。不新建字段，也不改现有作业状态或时间判据。
   - **执行失败不冒充零删拒绝**：前置拒绝仍为零删除。批准执行阶段若遇到后续 `unlink`、目录同步、SQLite 写事务或 checkpoint 失败（包括 `busy`），退 `2` / `gc_failed`，保留已确认提交的行、已成功 `unlink` 的文件数和逻辑字节数，以及已取得的 checkpoint 状态；文本错误也显示确认的删除。未确认的提交不能据计数断言零删。计数不等于实测可用空间，SQLite 与文件系统不具备跨存储回滚保证。

## 验证证据

- `uv lock --check`、`uv run --frozen ruff check .`
- 定向回归见 [GC 用例](../../tests/test_w15_safe_gc.py)。用例核对预演和平台拒绝时的零删除、SQLite 旁文件的保留、恢复隔离与解除证明、受保护引用及账本、真子进程维护互斥、POSIX 内核零写上限下的文件回收，以及余量不足时的表行延后。
- GC 执行错误定向回归（`tests/test_w15_safe_gc.py`）：后续 `unlink`、目录同步、SQLite 删除事务回滚及 checkpoint 错误逐项对账实际文件与表；另以真 SQLite 读进程管道屏障触发 checkpoint busy。
