# 摘要尝试隔离（2026-11-27）

本地候选基于 `9d5a02da23abda7a3b2ebf83ccdff26a83040a2b`，沿用现有摘要、共享预算和遥测格式。

- 原生成路径用固定的 `summary#<material_id>#1`，使同材料的新版本可能拿到旧预占。账本在额度和取消检查之前返回现有预占，新调用因此可能绕过准入并错用旧结算。每个新版本现在在持久化为 `pending` 时获得独立身份。预占与发送前遥测读同一条已提交记录，结算使用本次预占。
- 原路径把遗留 `pending` 标成 `failed` 后只回落一轮。现在再次遇到同材料时，即使达到版本上限也能结案。后续轮次遇到同材料 `failed` 时复用已有可用摘要或回落到确定性裁剪。新材料仍可在上限内生成，摘要功能默认关闭。
- 独立复审指出摘要的最新版本和上限原先在写事务外读取，且调用前缺少作业认领核验。候选按实际写锁内的状态作决定，核验作业仍归本次驱动。可发送的摘要版本、预占和发送前遥测同次提交。遥测写入失败会回滚准备事务。提交完成后才调用适配器，提交与发送间失去结果证据时按未知尝试处理。

## 验证范围

- 将相同测试放在基线上，确认旧代码复用预占、绕过请求和取消限制、重复尝试同材料及在版本上限处跳过结案。候选回归覆盖旧预占不变、不同新版本在发送前已持久化且与原始账本行对应、未知维度保留、`ready` 复用和默认关闭。见 [摘要尝试测试](../../tests/test_summary_attempt_identity.py)。
- 三份独立副本分别恢复固定身份、移除 `failed` 回落、恢复早于结案的版本上限检查。三组负控分别在尝试身份、后续轮次回落、版本上限处的结案断言失败。
- 复审增量用真实子进程在准备事务取得写锁前提交 `ready`、`failed` 或占用最后一个版本名额，也用子进程和注入时钟完成作业接管。旧候选错误地进入摘要调用，新候选读取已提交的版本或退出失去归属的驱动。SQLite 注入发送前遥测写入失败，验证版本和预占全部回滚。独立副本分别移除作业认领核验、把版本决策移回锁外、把发送前记录拆到下一笔事务，各自命中对应断言。
- 真实 `summary-after-call` 子进程以退出码 `77` 硬退。重开后可找到无回执遥测和绑定原尝试的预占，恢复后原预占仍为 `pending`，同材料版本转为 `failed`，摘要未重发。复现命令为 `uv run --frozen pytest tests/test_summary_cache_telemetry.py::test_sent_summary_hard_exit_leaves_unknown_record_and_resume_does_not_resend`。

- 第三轮用真实子进程在准备提交后完成接管，并用注入时钟单独验证认领过期。旧候选进入适配器，修订后旧实例不发送、不结算，保留已提交的准备证据。用 SQLite 触发器拦截正文写为 `ready`，以及同时拦截转为 `failed`，两种情况下主任务都能继续，摘要回执和结算均可独立核对。
- `summary-after-call` 的旧候选恢复结果误报精确次数。新候选报告未知并保留已有下界。另用进程硬退验证摘要回执已提交、游标尚未保存的情况。已有回执提高下界，暂停后二次恢复保持同一下界和原预算结算。见[摘要遥测测试](../../tests/test_summary_cache_telemetry.py)。
- 第四轮修复 OpenAI 兼容 JSON 可解析的孤立 surrogate 正文：`SummaryStore.complete()` 先把它拒绝为不可用 UTF-8 正文，主循环保留已经返回的遥测与预算结算后回落确定性裁剪，不替换字符、不重发。回归由真实 `OpenAICompatibleModel.complete()` 经本机 HTTP 服务返回转义 surrogate，并覆盖完整 Run。
- 第四轮在准备提交后的最终写事务内核验预算取消。独立子进程经管道屏障确认 `BudgetLedger.cancel()` 已提交后，旧执行者不进入 adapter；同次事务结案 `failed` 并释放确认未发送的原预占，不伪造结算。`is_cancelled()` 同时检查账户链；取消后新建的后代仍被祖先取消阻断，旁系账户不受影响。最终核验到远端接收之间仍保留不可消除的时序窗口。
- 第四轮在冻结副本中分别撤销 surrogate 拒绝、最终预算取消核验、祖先取消链和遥测 run 过滤。四组负控均因对应验收断言失败而非夹具错误；恢复后回归全绿。`read_calls(run_id=...)` 的定向读取与旧无过滤全库读取均有回归。

## 剩余边界

最后一次认领核验到远端接收之间存在时序窗口。可以拒绝核验时已失去认领的驱动。已在飞行的
请求仍可能返回，原预占和回执各按尝试身份结算。历史格式无法将摘要回执逐条归到保存游标之前或
之后，因此恢复近似为下界。精确恢复需要独立的版本化设计。最终主干上的裸全量、绑定代码与测试树
的独立复审和 GitHub required CI 尚待取得。
