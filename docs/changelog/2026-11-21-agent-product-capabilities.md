# 2026-11-21 · Agent 产品能力补齐候选

本轮把桌面任务、会话、模型和工具接线接到可执行的控制面。此文件描述候选代码，不代表已经合并或发布。

- [会话与计划](../M5-desktop.md#34-方法表v1)：追问保留所选运行的问答，运行中补充只在下一次生成前生效。计划保持只读，澄清或修订后明确确认才进入执行。`/compact` 生成下个 Run 的交接摘要。
- [文件收发](../M5-desktop.md#34-方法表v1)：文本和显式支持的 PNG/JPEG 输入，及基于 Receipt 的历史文本产物预览，通过内容哈希核对。
- [本机调度](2026-11-21-local-schedule-triggers.md)：日历、目录新增和认证本机事件。[本机 Webhook 接收器](2026-11-21-schedule-webhook.md)只监听回环；公网请求须经自行部署的 HTTPS 代理。
- [受限表单](2026-11-21-browser-form.md)：同一 Run 的静态同源表单可按完整参数单次批准提交；未确认的 POST 不重发。无脚本、登录态或文件上传。
- 默认离线演示可连续完成多个 Run。Daemon 启动和设置切回离线时共用无状态模型；一次性 CLI 的指定输出仍可生成占位报告。
- 模型档案固定本次选择与准入备用候选；发送后不切换。Responses 自动压缩由用户选择启用，并使用服务端返回的加密边界。原消息事件和审批留存，重放不联网。
- 网页搜索使用用户选定的 SearXNG JSON 端点。只读网页导航按任务白名单和逐次审批访问公开 HTTPS 页面，并核对本 Run 的来源链接。HTTPS MCP 使用固定地址、任务选取、执行边界和原有逐次审批；工具版本随握手会话变化，旧审批不迁移。三种公开工具在拨号前均拒绝私网字面量；域名使用既有的全结果集校验与端点固定。原 `network.fetch` 保留显式批准本机地址的行为。

独立复审发现两个控制面偏差：替换目标后仍可选择旧 Run 做 `/compact`，普通执行也可能与计划确认共享请求编号。修复后，手动压缩只接受当前修订的历史；自动摘要须沿经事件记录的连续追加修订传递。把目标替换后重新输入原文也不会恢复旧摘要。普通执行与计划确认不能用同一请求编号互相替代。

后续复审发现用第二个编号确认同一计划时，成功返回的编号没有入账；压缩重试也无法区分原请求是自动选源还是显式选源。控制面用追加的 `run.workflow_request` 把这些编号绑定到原 Run，并核对重试参数。该事件不改提示、审批或回放；缺少选源事实的旧压缩记录仍可回放，但不能用旧编号重试。详见[工作流契约](../compact-plan-contract.md#请求身份与重试)。

独立 TLS 探针还发现远程 MCP JSON 可在声明长度未读满时被误记为已执行，分块 SSE 可能接受错误的块分隔符。JSON 现在要求单一、有界且读满的 `Content-Length`，或拥有完整块分隔符、终止块及尾部终止空行的分块正文。分块 SSE 使用同一读取规则检查匹配事件所用的块，收到完整匹配事件后可在流关闭前返回。冲突分帧、超限或提前断流会保留结果未知，不生成 Receipt、不自动重发。

组合验证发现网络 Receipt 原先扩张了历史 v0/v1 schema。网络回执现在使用独立的 v2，
普通回执保留原版本。Responses JSON 与 SSE 也按相同规则处理发送结果不明的请求。
回环验收让服务端先完整接收 POST，再返回截断正文、503 或重定向，核对请求次数与持久化结果，
并以明确的 429 验证有界重试。未知用量继续保留预算占用。
后续独立回环发现分块和 SSE 末尾还可能被误当作完整响应。Responses 现在核对实际头部终止、
长度与分块尾部，并拒绝没有结束空行的 SSE 事件。MCP 复用同一分块校验器，保留收到完整匹配
事件后即可返回的语义。旧 Chat Completions 和 Anthropic Messages 在 SSE 自然读完时仍检查
声明长度；回环负控确认截断不会提交结果，也保持原传输错误分类。

Windows 主干 [44916124972](https://github.com/lorek666/tianshu-agent/actions/runs/44916124972)
的第一片在 97% 处达到 25 分钟上限。按两次 Windows 执行记录调整低估的文件权重。

缺失的尾部用前一轮的同文件耗时估算，回算不含收集和 runner 开销。仍用两个原生
runner、整文件分组与原顺序，25 分钟限制、诊断和严格覆盖核验均照旧。

的分片 0 再次达到上限，分片 1 已完成，required 汇总正确拒绝缺失报告。进一步对账发现，

历史工作量分配，新候选仍须独立完成本机门禁和 hosted required CI。
