## 原因与实现

一次 Run 成功不能表示用户目标已经验收。首版把条件、轮次与人工结论保存为可审计
事实，让用户能逐轮推进并核对结果：

- `/goal [正文]`、欢迎页目标入口与已有任务面板。创建只保存配置，点击“推进一轮”
  才创建并入队真实 Run；每轮手动继续，不承诺无人值守。
- Goal 绑定 Task 修订及固定执行资格；条件、最大轮次不可变。下一轮只承接同一
  Goal 自己的成功末轮最终正文，持久化为本轮输入；改目标或工作区使旧 Goal 失效。
- `goal.created`、`goal.round_started`、`goal.closed` 从 v1 开始；创建和关闭用既有
  Task scope，推进用本轮 Run scope。事件日志保持 append-only，Run、轮次与 Job
  在同一事务提交；相同 request_id 幂等，真实双进程争用不重复入队。
- `goal.get/create/advance/close` 只供本机控制面，GoalView 独立读取，不扩大
  首屏 `state`，不增加模型工具或授权能力。
- 成功后逐项勾选条件，再由人确认完成。失败、取消、空白最终正文以及
  `partial/unknown` 副作用结果均不能继续或验收。

## 整合主干时的边界

保留主干的 Responses 延续、已持久化 terminal turn、用量版本、附件、模型路由、
运行中补充要求和 `run.follow_up`。Skill 追问接入新的运行入口，不再修订 Task
目标；路径形式正文不误判为 Skill。同步前的全量、构建、浏览器和复审证据均只作为
历史，不外推到本候选。

G1 不保存附件和单次模型档案；两者组合会在新建 Task 前明确拒绝并保留草稿，
使用当前默认模型，不为 Goal 固定模型档案；运行中切换沿用既有每次模型步骤的
快照机制，不代表入队时固定档案。Responses 延续仍受既有 scope 绑定限制，
不承诺任意模型切换都能继续原上下文。任务级网络、MCP 与子任务配置继续沿用既有能力。
Goal 的远程 MCP 发现按现有桌面路径留给驱动线程，不在入队事务中联网。

本轮整合前已有 compact/plan 的等价实现合入主干，因此保留主干实现，再重放独立
回归、Skill 与 Goal 增量，避免用旧循环覆盖新契约。旧功能树与提交已保存在本地
ignored Git bundle、tree 与 patch；没有操作其他会话的工作树、索引或进程。

## 缺陷与真实负控

独立第二读者在同步前发现的高危问题已修复，并在整合对象上重新验证：

- 最终响应提交后硬退，恢复曾绕过人工否决；恢复必须走正常收尾判定。
- 相同窗口恢复曾提前结束仍有未完成子任务的父 Run；必须保持等待。
- 含真实 MCP `applied + unknown` 的 `partial` 曾被错误允许继续与验收；
  当前与 `unknown` 一并阻断。

本轮新增了附件/模型组合、错误携带 `goal_config` 到 `task.create`、
远程 MCP 提前发现的 RED→GREEN。首次 MCP 探针错误共用一个客户端导致普通 Run
也失败；改为独立 control/driver 客户端后，普通 Run 通过、Goal 确定性失败，
再修复 Goal。保留夹具错误和产品错误的各自日志，不把它们混称为产品失败。
