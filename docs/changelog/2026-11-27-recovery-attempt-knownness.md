# 恢复时保留模型尝试数的已知性

旧游标若缺少精确的模型尝试数，运行只用已完成轮次作为下限。再次读取曾保存的下限时，不能因为计数键存在就把它标作精确值。恢复会累加可核实的新尝试，同时保留原有的未知标记。

读取含非布尔已知性标记的游标时，CLI 手动恢复和桌面显式续跑都在认领作业前拒绝。读游标、校验和认领共用 SQLite 写事务；若上一位持有人在交还作业前保存了新游标，续跑会采用其最新提交。Worker 自动驱动不发送模型请求或改写原游标；`run status` 也拒绝把错误标记显示为精确次数。旧游标缺少标记但有计数时保留原有兼容语义。

回归使用真实游标编解码、事件库与恢复入口。另一进程实际认领、保存并交还作业，验证续跑使用最新合法下限，以及遇到畸形标记时不认领、不写游标、不发模型请求。模型边界使用离线脚本，不涉及真实模型调用。
