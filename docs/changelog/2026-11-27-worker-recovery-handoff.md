# Worker 启动恢复和心跳收尾

直接 Worker 的首次认领，以及 Daemon 的普通轮询和显式续跑，都要等子任务投影恢复成功。
恢复首错保留原异常，并阻断当前 Worker；Daemon 停止驱动。调度和后续认领不会从半完成的
恢复继续。新实例仍从持久化记录重新核对状态。

有界回收失败时，保留原心跳线程句柄和它使用的 SQLite 连接。当前驱动不能认领后续作业；
确认同一线程退出后才能关闭连接。作业结算或续跑清队也失败时，保留原异常，并在异常注记
中保存二次失败。原中断之后不自动推进 Goal。
Daemon 续跑心跳收尾的两条诊断也遵循同一规则；日志管道停止接收时，仍传播原中断。

旧候选的独立探针确认：预排的显式请求可在恢复前认领；恢复失败时排入的续跑也可在下一轮
认领。另外，次级清理异常能替换原 `KeyboardInterrupt`，或被 Daemon 当作普通续跑异常吞掉。
后续验收同时检查真实 SQLite 作业状态和认领版本、原事件序列、原异常对象，以及真正心跳
线程和侧连接的生命周期。日志失败回归使用已经关闭读端的真实管道。锁预算、心跳超时、
C3 事件格式和人工恢复规则不变。
