# 文本配置与环境变量凭据

日期：2026-11-22。由维护者明确要求：不再使用 Keychain，非敏感配置用文本记录，API Key 保存在环境变量中。
本文规定凭据迁移行为。最终安装包上的原生启动与核心任务验收单独记录。

## 原方案 → 新方案 → 原因 → 影响

原方案在 macOS 默认使用 Keychain，桌面设置可写入和删除密钥；环境变量主要用于开发。
新方案在所有平台只从启动进程的环境变量读取 API Key，桌面设置只保存非敏感 JSON 文本。
维护者选择此方案以去除 Keychain 使用和原生验收依赖。环境变量不是操作系统安全存储，
不承诺防止同用户进程检查或崩溃内存泄漏；执行子进程的既有最小环境与脱敏规则仍须保留。

影响 `credentials.py`、`settings_control.py`、模型配置与档案、设置界面、使用说明和发行验收。
五道契约的模型消息、工具、事件、授权与评测语义保持不变。

## 配置与运行

- `<data_root>/model_config.json` 与 `model_profiles.json` 继续保存模型名、端点和能力开关等非敏感设置。
  新配置的 `credential_backend` 只接受 `env`；API Key、token、secret 等敏感字段仍须拒绝，不能写入配置或事件。
- OpenAI 兼容 Chat / Responses 沿用 `TIANSHU_API_KEY`；Anthropic 沿用 `ANTHROPIC_API_KEY`。
  不引入 `.env` 自动加载或应用内密钥文件，也不通过设置 RPC 修改父进程环境变量。
- 设置界面仅展示变量名与是否已配置，移除 Keychain 选择、密钥明文输入及保存/删除入口。
  原 `credential.set/delete` RPC 保留明确失败行为，不能假装已持久化或删除环境变量。
- 不访问系统钥匙串，不读取、搬移或删除以前存放在系统钥匙串中的密钥。
  `TIANSHU_CREDENTIAL_BACKEND=keychain` 的显式旧选择应给出停用提示，不能隐式读取另一个后端。
- 环境变量必须由实际启动 App / Host / Daemon 的环境提供；已启动进程不会因外部终端修改变量而更新。
  Finder 启动不保证继承 shell 配置，使用说明须给出从已配置终端启动的方式，不声称自动获取 shell 环境。

## 旧数据

- 旧 `model_config.json` 与 `model_profiles.json` 中明确的 `keychain` 选择，在加载当前可编辑设置时转成 `env`，
  不读取旧密钥，不在加载时覆写磁盘。下次保存才写入新选择；其他非法值仍报错。
- 已持久化的 `run.model_route` 是事实：历史 schema 保留 `keychain` 值用于校验与回放，不改写事件。
  绑定旧 Keychain 路由继续执行时明确拒绝，提示使用环境变量配置启动新 Run；不把历史路由悄悄改成 env。

## 发布验收

Keychain 不再是发布条件。改为用最终安装包验证启动环境中设置凭据、重启后读取、未配置时明确失败、
响应/日志不泄密以及核心任务。required CI、原生启动、安装/升级/回退、恢复和数据完整性门禁不变。

## 实施选择

沿用现有 JSON 与凭据分域接缝，移除系统凭据后端。保留 Keychain 作为可选后端会继续引入本次要求去掉的
入口和原生访问；另建明文密钥文件则不符合“key 保存在环境变量中”。因此两者均不采用。
